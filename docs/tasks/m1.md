## The contract: facts JSON
The authoritative schema is `schema/facts.schema.json` (JSON Schema 2020-12); if this summary and the file disagree,
the file wins. Fixture: `site/fixtures/facts.sample.json` (FIXTURE data, `"fixture": true`, made-up names, URLs on
`example.invalid`). It validates against the schema and exercises: an absence, a "Recused" vote (`other`), a held-back
roll call (`tally_matches_stated` false), a meeting with attendance not extracted, an item across two meetings, and an
item linked by title.

```
{
  "schema_version": "1.0",
  "fixture": true,                                   # fixture files only
  "coverage":    {"body", "from", "to"},
  "sources":     [{id "src-<sha12>", url, sha256, kind minutes|agenda, meeting_date, fetched_at, pages, text_layer text|ocr|none}],
  "officials":   [{id slug, name, surname, given, title, aliases[]}],
  "meetings":    [{id "<date>-<kind>", body, date, kind formal|informal|special, source_id,
                   attendance_status extracted|not_extracted,
                   attendance [{official_id|null, raw_name, status present|absent, page}],
                   stated_absent_count|null, verification}],
  "items":       [{id, number|null, title, link_basis number|title, year}],
  "item_events": [{id "ev-<sha8>-p<page>-<n>", item_id, meeting_id, date,
                   type listed|referral|reading|amendment|motion|roll_call|postponed|withdrawn|other,
                   label (verbatim), ref (motion/roll call id)|null, source_id, page, order}],
  "motions":     [{id "mo-...", meeting_id, item_id, text, moved_by {official_id|null, raw_name}|null,
                   seconded_by (same)|null, source_id, page, verification}],
  "roll_calls":  [{id "rc-...", meeting_id, item_id, motion_id|null,
                   votes [{official_id|null, raw_name, value yes|no|abstain|other, raw_value}],
                   stated_tally {yes,no,abstain}|null, outcome passed|failed|other, outcome_text, source_id, page,
                   verification}],
  "corrections": []                                  # reserved for M1.5
}
verification = {status verified|unverified, checks [{check, ok, detail?}]}
```
Every list sorted by id; file written with sorted keys, 2-space indent, trailing newline.

## Backend (`backend-engineer`)
Parallel with all frontend tasks. B1 and B2 can start now; B3 needs the M0 parser.

**B1. Polite fetcher and document store.** Files: `collector/fetch.py`, `collector/store.py`, `tests/test_fetch.py`,
`tests/test_store.py`; add `requests`, `pyyaml` to `requirements.txt`.
- In: URL list. Out: `data/store/<sha256>.pdf`, `data/manifest.json` entries (fields in architecture "Document store").
- Done: tests with a fake transport and fake clock prove (a) a robots-disallowed path is never requested, (b) the
  per-host delay is never skipped (10 s floor on `clarksvilletn.gov`, 5 s elsewhere, robots Crawl-delay if larger),
  (c) 403/429 stops the host for the run with no retry by another route, (d) `cityofclarksville.com` is refused,
  (e) re-storing identical bytes leaves `manifest.json` byte-identical. (AC4.2, AC4.3, AC4.5)

**B2. Minutes discovery.** File: `collector/discover.py`, `tests/test_discover.py` (saved HTML fixture of the index page).
- In: `https://dev2.montgomerytn.gov/clerk/county-commission-minutes`. Out: list of {url, meeting_date, kind} for 2020-2024.
- Done: fails loudly (non-zero exit, logged) if the page moves or lists nothing; never guesses other hosts (A4).

**B3. Names, verifier, facts assembly.** Files: `collector/names.py`, `collector/verify.py`, `collector/facts.py`,
`data/names.yml`, `data/procedural-titles.yml`, `tests/test_names.py`, `tests/test_verify.py`.
- In: M0 parser output (`parse_minutes(pdf_path, source) -> ParsedMinutes`, raw names, no verification).
- Out: `data/facts.json` valid against the schema; `build/report.json` (verified rate, held-back rate per official,
  gate results); `build/name-candidates.json`.
- Done: merge rules 1-4 and every check in architecture "Verifier" implemented and unit-tested; a test validates
  `data/facts.json` against the schema; the hand-labelled set from M0 (AC-P3, 15+ roll calls) gives zero wrong votes;
  G4 gate uses `SKEW_FACTOR=2.0`, `SKEW_FLOOR=0.02` from `collector/config.py`; item numbers normalised per architecture
  "Item history", with a test that a non-matching raw number becomes unnumbered, never guessed.

**B4. Export, run log, CLI.** Files: `collector/export.py`, `collector/__main__.py`, `tests/test_run.py`.
- Out: `build/site/data/*.csv` and `build/site/data/facts.json` (verified only); `build/run-log.json` (found, new,
  failed, parsed, held back). `python -m collector run [--offline] [--internal]` calls `sitegen.build`.
- Done: export contains no unverified fact (test); a second `run --offline` changes no committed file (test, AC4.5);
  exit codes 0/2/3 as in the architecture; on exit 2 or 3 `run` prints the `gh issue create` command it would run
  (actual issue creation wired in D1).

## Frontend (`frontend-engineer`)
Build against `site/fixtures/facts.sample.json`; the real facts drop in unchanged.

**F1. Generator skeleton and base layout.** Files: `sitegen/__init__.py`, `sitegen/__main__.py`, `sitegen/config.py`,
`sitegen/build.py`, `sitegen/views.py`, `site/templates/base.html.j2`, `site/static/style.css`; create
`requirements.txt` with `jinja2`, `jsonschema`, `pytest` (backend appends its own).
- `python -m sitegen --facts site/fixtures/facts.sample.json --out build/site [--internal]` validates the input against
  the schema, renders, copies static. Writes `build/publish-files.json` ({published path: local path}, index.html
  excluded) and fails if the site exceeds 250 files.
- Base: `<title>` "Clarksville Records" + page name; footer on every page: "Run by {OPERATOR_NAME}. About this site and
  its data rules." linking `about.html`, plus "Data as of <newest fetched_at>". `OPERATOR_NAME =
  "[OPERATOR NAME - CEO to confirm]"` in `sitegen/config.py`; warn on build while it is the placeholder. FIXTURE
  banner on every page when `fixture` is true. CSS: colour tokens on `:root`, dark variant via
  `prefers-color-scheme`, explicit body background, 16 px gutter, tables scroll in their own box. No external
  scripts, fonts or trackers.

**F2. Officials index and official page.** Files: `site/templates/index.html.j2`, `site/templates/official.html.j2`,
`site/static/filter.js`, `views.officials_index`, `views.official`.
- Index: names only, sorted by (surname, given) casefold, linking `officials/<id>.html`.
- Official page, fixed section order for everyone: name and title; coverage sentence (AC1.4); the three fixed totals
  sentences (architecture N3/P4/AC2.3); type filter (Vote, Attendance, Moved, Seconded) and year filter; one history
  table, newest first: Date | Type | Item | Record | Outcome | Source. Vote rows link the item
  (`../items/<year>.html#<item_id>`) and meeting; Source shows "p. N, fetched <date>" linking `<url>#page=N` in a new
  tab; each row shows its fact id and a "Report an error" link to `../about.html#corrections`. Only verified facts.
  Empty sections show a fixed sentence, never disappear.

**F3. Meeting and item pages.** Files: `site/templates/meeting.html.j2`, `site/templates/items_year.html.j2`,
`views.meeting`, `views.items_year`.
- Meeting: date, kind, source link; attendance table alphabetical (or "Attendance not extracted for this meeting.");
  then motions and verified roll calls in document order, each roll call with every member's vote (alphabetical) and
  outcome; held-back roll calls as one fixed sentence with the count, no values.
- Items: one file per year, one `<section id="<item_id>">` per item: number or title, "linked by number" / "linked by
  title", events in (date, page, order) order with verbatim labels and source links; roll call events expand to the
  full vote table. (AC7.1-7.4)

**F4. About, changes, review pages.** Files: `site/templates/about.html.j2`, `changes.html.j2`, `review.html.j2`.
- About: operator (OPERATOR_NAME), what is collected and from where, verified/held-back rule, name merge rules and the
  alias table (from facts `officials[].aliases`), neutrality rules N1-N6 in plain words, `#corrections` (preview text:
  "Comment on the page and quote the fact id."), links to `data/*.csv` and `data/facts.json`.
- Changes: list from `data/changes.jsonl` if present, else "No changes recorded yet."
- Review (`--internal` only): every unverified fact with its failed checks and source link; gate results from
  `build/report.json` if present. Not linked from public pages.

**F5. Neutrality and link tests.** Files: `tests/test_site_neutrality.py`, `tests/test_site_links.py`.
- AC1.5: render two fixture officials, reduce each page to its skeleton (tag names, headings, column headers, section
  ids), assert equal.
- Template lint: fail on banned words (`rank`, `score`, `grade`, `missed`, `percent`, `%`, `best`, `worst`) in
  `site/templates/` and on any sort by a count.
- AC1.3: every fact row in the built site has a source link with `#page=N` where 1 <= N <= the source's `pages`.
- AC2.2: the attendance totals on each official page equal a recount from the meeting pages.
- No unverified fact id from the fixture appears in any page except `review.html`.
